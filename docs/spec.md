# SessAnchor 專案規格

更新日期：2026-09-22。狀態：需求基線；已開始核心契約原型，實作進度見 [implementation.md](implementation.md)，不代表以下需求皆已完成。

本文整理本 session 已確認的產品需求；「待確認」與「待驗證」不代表已承諾的實作方案。階段順序為建議，不縮減最終支援範圍。

## 1. 定位與範圍

SessAnchor 是供 AI coding agent 與使用者操作遠端主機的 SSH 工具，提供 CLI 與 MCP，共用 Rust 核心。專案／npm 套件預定名稱為 `sessanchor`，主要指令為 `sanc`，保留 `sessanchor` 別名。名稱與發布資格須於發布前重新確認。

核心價值：快速建立、重用與恢復連線；追蹤遠端指令、輸出與故障；降低 agent 反覆組合 Bash／SSH 指令及閱讀大量輸出的成本。

- 管理裝置連線、session、指令與檔案，不管理 agent 的生命週期、身分或工作流程。
- 不取代 tmux、shpool；可在必要且經授權時使用遠端持久化後端。
- CLI 與 MCP 必須提供一致的狀態、控制權及安全語意。
- 本機與遠端均以 macOS、Linux、Windows 為支援目標，不能把某一 Unix 後端等同跨平台支援。
- 單一本機 OS 使用者範圍；不建立多使用者服務、帳號系統或對外遠端管理 API。

## 2. 裝置與連線

### 2.1 設定與認證

- 具有獨立裝置設定與 CLI 參數；可選擇匯入／參考 `.ssh/config`，但不可只依賴該檔案。
- 支援密碼、私鑰、私鑰密語與 SSH agent；支援單層及多層跳板，各跳點可使用不同認證。
- 認證資料透過安全輸入或適當憑證儲存處理，不寫入 log 或送入 AI context。
- 缺少認證時回報等待認證，故障時指出失敗跳點，不籠統歸類成目的主機離線。
- 主機指紋政策見「待確認」；不得將略過驗證當作減省 context 的措施。

### 2.2 背景維護與休眠

- 本機背景服務維護當次開機後成功連線過的裝置，定期檢查連線健康。
- 可查詢可用、不可用、重連中、等待認證、休眠及未知等情況，附最後成功／檢查時間、原因與重試資訊。
- 閒置休眠預設 2 小時，可全域或逐裝置設定，也可停用。
- 健康檢查不重設閒置計時；休眠表示釋放 SSH 連線並停止探測，不是讓遠端主機睡眠。
- 下一次操作喚醒並重連；一般執行中的指令與傳輸阻止休眠，完成後才開始閒置計時。
- 明確分離且確認可獨立存續的工作可另行允許連線休眠，不可默認所有工作均具此能力。
- 重連只恢復連線／查詢任務，不隱含重新執行指令。

### 2.3 常用裝置

- 提供快速清單，依近期使用頻率排序，支援手動置頂，跨本機重開機保留。
- 顯示別名、位址、作業系統名稱與版本、連線狀態、最近使用時間及系統資訊更新時間。
- 先讀本機快取，不等待逐台連線；成功連線時更新系統資訊，不為刷新清單喚醒休眠連線。
- 重開機後舊狀態不可當作即時健康狀態。歷史裝置保留不代表所有裝置都立即納入背景探測。
- 系統資訊取得失敗時標示未知或過期，不猜測版本。

## 3. Session、指令與恢復

### 3.1 隔離與追蹤

- 同時支援有 shell 狀態的互動 session 與可獨立追蹤的指令任務。
- 以 session ID 隔離工作目錄、環境、輸入與任務狀態，不以 agent 身分作為隔離單位。
- 此隔離不是 OS 安全沙箱；相同遠端帳號仍共享檔案系統權限。
- 每項任務可追蹤裝置、session、任務 ID、時間、狀態、輸出與 exit code；未確認退出不可捏造 exit code。
- 執行請求預設短暫等待；完成就回結果，未完成就回任務 ID，後續查詢狀態及增量輸出。
- 在具持久化能力的模式下，呼叫端退出或網路中斷不終止遠端工作，之後可重新連線查看。
- 不具此能力時必須明確揭露限制；遠端重開機存續不在默認保證內。

### 3.2 重試與去重

- 使用 `request_id` 識別同一執行請求；重送回原任務與狀態，不再次執行。
- 相同 ID 搭配不同指令／執行參數時拒絕，不覆蓋原請求。
- 無法確認是否已執行時回報 `unknown`，不得自動重跑，也不得將其視為閒置。
- 去重的作用範圍、保存期限、持久化及跨服務重啟邊界待設計；不得宣稱已解決分散式 exactly-once。

### 3.3 Session 說明

- 呼叫端可寫入簡短 description，說明目的、已做事項與下一步，附更新時間。
- 系統另外提供有限筆近期指令、exit status 及未完成工作；不要求下次呼叫端讀完整 log。
- 人工／agent 描述與系統觀測分開，過期描述不能覆蓋當前事實。
- 呼叫端結束後，可透過明確 session ID 繼續使用；不可自動搶占仍在使用中的 session。

## 4. 使用者觀察與接手

- 本機互動 CLI 可選擇 session，查看裝置、description、狀態、目前指令／傳輸、耗時、即時輸出與近期事件。
- 預設唯讀；退出觀察介面不停止任務。
- 使用者必須等目前指令結束才能接手。接手時再次檢查狀態並取得獨占輸入權，避免與新指令競爭。
- 可經明確確認取消卡住的任務，但必須確認已停止才能接手；取消請求送出不等於取消成功。
- 使用者接手時標示 `user_controlled`；agent 可查知狀態，執行／輸入請求立即拒絕，不排隊、不自動搶回。唯讀查詢仍可用。
- 正常退出互動介面自動釋放控制權；若使用者啟動的指令仍在執行，維持忙碌，完成後才可接手。
- CLI 意外關閉／斷線後保留控制權 30 秒，逾時自動釋放；若指令狀態未知仍禁止接手。
- 控制權取得與釋放記錄成事件；釋放不會自動恢復 agent 先前操作。
- 連線狀態、任務狀態與控制權須分開表達；釋放控制權不代表任務已停止。

## 5. Context 預算與整合

### 5.1 精簡回應

- agent 預設取得精簡結構化結果，欄位及狀態代碼使用穩定英文；人類介面與說明可依語言設定呈現。
- 成功只回必要 ID、狀態及結果；失敗保留錯誤原因與可行下一步。
- 單次指令輸出預設上限 4 KiB；超出附截斷標記及後續讀取游標。狀態與錯誤中繼資料不可因輸出截斷消失。
- 依游標讀取增量，不重送已讀 log；完整輸出依保留政策存放，不因單次回應截斷而刪除。
- 常用裝置、OS 版本、session description 與完整紀錄按需查詢，不隨每次操作注入。
- 大量輸出提供有界預覽／摘要與檔案參照；摘要不替代原始證據，不要求內建 LLM。
- hooks 只提供相關的重要狀態變更並去重，不反覆注入健康檢查與完整使用指南。
- 4 KiB 是位元組預算，不是 token 保證；UTF-8 邊界、stdout／stderr 分配及整體回應預算待定。

### 5.2 Claude Code、Codex 與 context-mode

- 提供 Claude Code 與 Codex 可使用的 CLI／MCP 入口、精簡 hooks 與 skills，支援多語言使用情境。
- 整合是薄層使用指引／狀態介接，不延伸成 agent 管理平台。
- 實際 hook 事件、MCP 能力及權限流程須依各平台當時官方文件驗證，不假設兩者相同。
- 可與 context-mode 搭配：SessAnchor 保存可追蹤輸出檔案，必要時供外部工具索引／搜尋／處理；不先把完整 log 塞入 context 再轉交。
- 不依賴 context-mode 才能正常運作，也不重造其完整搜尋或沙箱系統。
- 輸出參照須可被整合端實際讀取；路徑存續、權限、更新及索引過期問題須驗證。

### 5.3 以 hooks 引導 AI CLI 正確操作

- 已確認：同時參考 context-mode 的 hook 設計，讓 Claude Code／Codex 能在相關操作時準確使用 SessAnchor，而不只依賴 agent 記住 skill。實作前須查驗 context-mode 當時的實作及各平台官方文件；以下是本專案需求，不是對既有平台能力的斷言。
- 在平台支援的事件上按需提供精簡引導：遠端操作優先使用已設定的 SessAnchor 入口、重試沿用原 `request_id`、追蹤沿用任務／session ID、輸出依游標增量讀取。
- 遇到 `user_controlled`、`unknown`、等待認證或需要安裝授權時，提示正確下一步，不引導自動搶占、重跑或繞過批准。
- 僅在相關呼叫或狀態變更時觸發，提示去重、有界且可按需展開；不每次注入完整指令手冊或裝置清單。
- hook 不無聲改寫任意 SSH／shell 指令，也不代替使用者同意；真正的控制權、去重與安全限制由共用核心執行，不依賴模型遵從提示。
- 與 context-mode 同時安裝時須驗證 hook 順序、重複提示及衝突，避免互相反覆轉送；不具對等 hook 能力的平台採精簡 skill／工具回應降級，明示限制。
- 驗收涵蓋有／無 context-mode、有／無 hooks、錯誤重試及使用者接手；確認引導正確、提示不重複，並量測額外 context 成本。

## 6. 檔案操作

### 6.1 一般傳輸與同步

- 支援上傳、下載與目錄同步；常見內容包含 exe 安裝檔、sh／ps1 腳本。
- 保持原始位元組、編碼與換行，不自動執行腳本或安裝檔。
- 先檢視來源／目的路徑、差異、覆寫與刪除計畫，以精簡結構化結果讓 agent 在既有授權內決定，或向使用者詢問。
- 執行前重新檢查目的端是否改變，完成後驗證內容；計畫過期不可無聲覆蓋新資料。
- 不默認具有刪除授權；驗證演算法、同步衝突與 metadata／symlink 政策待定。

### 6.2 超大型檔案

- 設立專用 `sanc transfer` 指令族，提供傳輸 ID、進度、暫停、取消與續傳。
- 呼叫端退出後可背景傳輸；活躍傳輸阻止連線休眠。
- 保存續傳 metadata，支援本機／背景服務重啟後恢復；需檢查來源有無變更，驗證既有區塊，再傳缺少部分。
- 先寫暫存目的檔，完整驗證後才替換正式檔案；平台上的替換原子性與衝突處理須驗證。
- 中斷與來源變更不得造成錯誤的成功回報；取消後暫存檔保留／清理規則待定。
- 以相同加密與完整性條件，對照 rsync 測試大小檔、安裝檔、延遲、中斷及續傳情境；更安全／更快是評估目標，不是未測量的保證。

## 7. 日誌、授權與遠端 helper

- 硬性規則：指令去除前導空白後若以 `sudo` 為首個詞，核心拒絕提交，回報 `approval_required`，AI 必須停下來告知使用者，不可自動重試、改寫繞過或自行代表批准。目前不提供 override；後續批准機制須另行設計。這是字面前綴規則，不是完整 shell 提權偵測。

- 記錄經本工具發起的連線、指令、重試、睡眠／喚醒、傳輸及控制權事件，透過 ID 關聯。
- 日誌預設保留 7 天、總量 1 GiB，可設定；優先清理已完成工作的舊輸出，讀取時標明已過期。
- 活躍輸出達容量上限時的策略待定；不可默默丟資料卻仍聲稱完整保存。
- 秘密資料不得寫入日誌；一般命令輸出仍可能含敏感資訊，遮罩、權限及保留邊界須另行設計，不承諾萬用自動辨識。
- 本機背景服務僅開放本機、適當使用者權限的存取；傳輸通道及存放資料需安全設計。
- 尊重呼叫平台的授權流程，並可規劃逐裝置操作政策；不能假設 Bash 的批准規則自動套用至 MCP／本工具。
- shpool 是候選的可選持久 shell 後端，不是基本 SSH 的必要依賴，也不取代每指令 exit code 與持久 log 追蹤。
- 安裝任何必要遠端 helper 前，先說明用途、位置、動作及權限，取得使用者明確同意；需要提權時另行取得批准。agent 不得自行代表同意。
- 優先使用既有安裝或使用者目錄、不需 root 的方式；拒絕安裝仍可使用基本 SSH，並明示缺少的持久化能力。

## 8. 架構方向與待驗證技術

以下為候選架構，不是已完成選型：Rust 共用核心承載裝置／session／任務模型；本機 daemon 維護 SSH 連線、狀態與輸出；CLI／MCP 作為入口；遠端持久化透過能力探測與可選後端提供。

| 項目 | 驗證工作 |
| --- | --- |
| Rust SSH 實作 | 認證、SSH agent、多跳、host key、跨平台、取消與重連行為 |
| 持久化後端 | 各 OS 的可用後端、斷線存續、重新附接、完整輸出及 exit code；不能假設 shpool 支援全部平台 |
| 本機 daemon | IPC 存取控制、單例、崩潰恢復、開機界線、輸入控制權到期及競爭條件 |
| 任務提交 | 持久化去重、送出／確認間斷線、服務重啟與 unknown 的恢復方式 |
| 檔案傳輸 | 傳輸協定、校驗與區塊策略、續傳 metadata、目的端競爭與替換安全性 |
| npm 發布 | Rust 預編譯平台套件、CPU 架構、完整性／來源驗證、安裝失敗與移除行為 |
| agent 整合 | 依當時官方文件驗證 Claude Code／Codex hooks、skills、MCP 及授權能力 |

此規格不把先前查閱的第三方文件視為目前版本或跨平台能力的證明；實作選型時須重新驗證。

## 9. 尚待確認的產品決策

1. 主機身分（已確認）：未知指紋由使用者確認，已知指紋變更停止連線並要求核對，agent 不可自動略過。目前 probe 只接受既有信任，尚未提供首次確認介面。
2. 具體健康檢查週期、重試退避／上限與失聯判定。
3. `request_id` 作用範圍、保存期限及過期 ID 處理，並與 7 天日誌保留分開。
4. 短暫等待時長、回應 schema、輸出游標存續與日誌容量耗盡政策。
5. 各 OS 最低版本／CPU 架構、helper 能力矩陣與不具持久化能力時的降級表現。
6. 傳輸路徑／連結／權限語意、刪除授權、來源快照與取消後暫存清理。

除已確認的 `sanc`、`sessanchor` 與大型檔案 `sanc transfer` 方向外，完整子指令／MCP 工具名稱及參數仍待介面設計。檔案上傳後自動執行並未獲得需求確認。

## 10. 建議實作階段

1. **技術驗證與介面契約**：建立跨平台能力矩陣、SSH／helper 小型驗證、狀態模型、去重與精簡回應契約，釐清安全待定事項。
2. **連線與可追蹤指令核心**：Rust core、daemon、CLI、獨立設定、認證與多跳、重連、健康檢查、休眠、狀態與日誌；先以故障測試驗證不重複執行。
3. **持久 session 與使用者介面**：後端能力與安裝同意、session 隔離／description、唯讀觀察、接手／釋放／取消、常用裝置與 OS 快取。
4. **MCP 與 agent 整合**：共享核心、Claude Code／Codex 精簡 hooks／skills、多語言及 context-mode 相容性，量測 context 使用量。
5. **檔案與大型續傳**：一般傳輸／同步、計畫驗證、背景大型傳輸與跨重啟續傳、rsync 對照測試。
6. **發布與跨平台驗收**：npm 預編譯套件、安裝／升級／移除、安全驗證及完整能力矩陣。早期里程碑缺少功能時明示，不稱為全部需求已完成。

## 11. 核心驗收情境

- 不存在 `.ssh/config` 時仍能以独立設定建立連線；支援的認證與多跳情境均有測試。
- 已連線裝置失聯後顯示可判讀原因與恢復狀態；2 小時閒置進入休眠，探測不延長閒置，活躍工作不被睡眠中斷。
- 遠端開始執行後中斷回應，再以相同 `request_id` 重試不產生第二次副作用；結果不明時回報 `unknown`。
- 具持久化能力的 session 在呼叫端退出／網路中斷後可恢復查看；不具能力者清楚揭露限制。
- agent 與使用者同時要求輸入時只有一方取得控制權；使用者控制期間 agent 收到可機器判讀的拒絕。
- 使用者正常退出自動釋放；意外斷線 30 秒後釋放，但執行中或未知任務仍不可被接手。
- 大輸出單次預設不超過 4 KiB 輸出內容，保持有效文字／結構、截斷標记及游標，後續讀取不漏接或重送；過期輸出明確標示。
